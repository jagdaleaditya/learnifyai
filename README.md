# LearnifyAI · Verified Course Material Studio

React + TypeScript + Tailwind front end with a small Node API that talks to **Groq** and **Ollama Cloud**, runs every generated snippet, auto-fixes failures, and exports real PPTX / PDF / ZIP files.

## Quick start

```bash
npm install
npm run dev:all        # API on :8787 + web app on :5173
```

Open http://localhost:5173 and sign in with any password of 6+ characters.

Keys are in `server/.env` (already filled in). They are read only by the Node server and never reach the browser bundle.
If `server/.env` is missing, copy `server/.env.example` and add your keys.

Other commands: `npm run build` (type-check + production build), `npm start` (build, then API + preview on :4173).

## What is real when the API is running

| Area | Behaviour |
|---|---|
| Create Course | Streams real progress. The model writes slides, notes, quiz, cheat sheet, examples and exercises; every snippet is executed; failures are sent back to the model (max 3 attempts). |
| Studio | Edit slides, regenerate one slide with the model (its code is re-run), run examples, run exercise tests (PASS/FAIL lines), load the reference or naive solution, fix a failing example with AI. |
| Code Verification | Run All / Run Selected on this machine with Java, Python, Node or TypeScript. Real failures, real auto-fix attempts, results saved to the course. |
| Reports | Per-snippet attempts, logs and timings from the actual run. PDF download is generated by the server. |
| Exports | PPTX (with speaker notes), slides PDF, trainer notes, quiz, cheat sheet, code ZIP, exercises ZIP, verification report, full package. |
| AI assistant | The sparkle button in the top bar. Answers use your verified course material as context. |
| Settings → AI & Training | Connection test, knowledge-base stats, dataset downloads, paste your own material. |

If the API is not running the app falls back to its built-in sample course and says so ("Sample mode").

Verification needs the toolchains on the machine running the server: **Java 21 (javac), Python 3, Node 20+**. React, Docker, SQL and similar courses are generated but marked unverified, because there is no runner for them.

## "Training": what it is and is not

Groq and Ollama Cloud serve models. They do not train weights from this app. What this project does:

1. **Retrieval learning.** Every course that passes verification is saved to `server/data/verified.jsonl`. Later generations retrieve the most relevant verified examples (TF-IDF ranking) and use them as grounding, so quality rises as you verify more. The 35-record seed comes from the sample course (`npm run seed` rebuilds it).
2. **Your own data.** Paste material in Settings → AI & Training, or ingest folders: `npm run ingest -- ./my-notes Java` (.md .txt .java .py .js .ts .json .jsonl).
3. **Fine-tuning set.** `GET /api/dataset?format=chat` (also in the settings tab) downloads chat-format JSONL. Use it with Unsloth, Axolotl or a provider fine-tuning API on a GPU to train real weights.
4. **Ollama Modelfile.** `npm run modelfile [base-model]` writes `server/data/Modelfile` with the best verified examples as few-shot messages: `ollama create learnify -f server/data/Modelfile`.

## Security notes

See **SECURITY.md** for the full list of protections and the HTTPS production checklist. In short:

- Production: Nginx with HTTPS (`deploy/nginx.conf`) in front of the API, `server/.env` based on `server/.env.example` (`NODE_ENV=production`, `ALLOW_REMOTE=1`, `TRUST_PROXY=1`, `FORCE_HTTPS=1`, `ADMIN_TOKEN`).
- Generated code runs with a 10 s timeout, memory caps and an environment that contains **no API keys**. It is still not a full sandbox: run the server as a non-root user, ideally in a container.
- Rotate any key that was shared or zipped, and never commit `.env` files (they are in `.gitignore`).
